01 — Capabilities

Built for long-horizon work,
not throwaway chats.

Every subsystem is designed to persist, recall, and compound — the opposite of a stateless chatbot wrapper.

/01

Persistent memory cabinet

MEMORY.md holds world facts, USER.md holds who you are — FIFO-bounded at 2.2K/1.4K chars so context never bloats. Every past session is FTS5-searchable from SQLite.

/02

Skills it writes itself

Finish a task once — the agent distills the procedure into an executable SKILL.md package and loads it into every future session automatically.

/03

Full-screen terminal TUI

Textual app: docked header, scrollable transcript, tool-call cards, and the live telemetry bar — context gauge, stream health, latency, token flow.

/04

Any provider, mid-session

Thirteen built-in providers plus custom for any OpenAI-compatible endpoint. Masked key entry with a live connection test before anything saves.

/05

Gateway + channels

FastAPI server on :8642 speaks OpenAI-compatible /v1/chat/completions — point Open WebUI or your stack at it, or bridge to Telegram, Discord, Slack.

/06

Cron & subagents

Natural-language scheduled jobs with memory injection, plus parallel subagent delegation that collapses long task chains into zero-context-cost turns.

The setup wizard runs a live connection test against your real endpoint before saving anything. API keys are masked on entry and stored in AEX_HOME/.env — never in config.yaml.

04 — Getting started

Four steps. Then
it runs itself.

A straight path from zero to a working agent — no accounts, no dashboards, no lock-in.

STEP 1

Install

pip install git+https://github.com/authxibu-cyber/AEX-Agent — or run the platform installer: .\scripts\install.ps1 (Windows) / ./scripts/install.sh (Linux, macOS, WSL).

STEP 2

Connect

Run aex setup. Pick a provider from the numbered table (or custom for any OpenAI-compatible endpoint), paste your API key — the wizard tests the connection live before saving.

STEP 3

Chat

Type aex. You're in the full-screen TUI: scrollable transcript, tool-call cards, and the telemetry bar at the bottom showing context, latency and stream health.

STEP 4

Let it learn

Finish real tasks. Ask /learn <name> <description> and the agent writes a reusable SKILL.md it loads in every future session. Close the terminal — everything persists.

05 — Reference

Everything you can type.

Shell commands for daily driving, slash commands inside the chat, and keys that control the TUI.

Shell — aex <command>

aex

Launch the full-screen interactive TUI. First run guides you through setup automatically. This is where you'll live.

aex chat [--classic]

Same chat, choose your interface — full-screen TUI (default) or the classic inline terminal.

aex setup

Interactive wizard: provider, model, base URL, masked API key, live connection test. Safe to re-run any time.

aex doctor

One command, full health check: repairs the aex command (Windows non-admin PATH), then live-tests your provider connection and tells you exactly what to fix.

aex model [name] [-p provider]

View or switch the active model/provider without opening a chat.

aex memory

Inspect the persistent MEMORY.md and USER.md files and their character budgets.

aex skills

List every loaded skill — bundled ones plus the ones the agent taught itself.

aex gateway [--port 8642]

Start the OpenAI-compatible API server + cron scheduler. Point any client at http://localhost:8642/v1.

aex cron

List scheduled background automations.

aex tools

Show the registered toolsets (terminal, file, web, memory, skills, code execution…).

Inside the chat — slash commands

/help

List every command below — you never have to memorize this page.

/model [name] · /provider [name]

Switch model or provider mid-conversation, on the fly.

/memory

See what the agent remembers about the world and about you.

/skills · /learn name description

Browse loaded skills, or have the agent author a new one from the current session.

06 — FAQ

Before you ask.

Which API keys work?

Any of the 13 built-in providers — OpenRouter, Nous Portal, OpenAI, Anthropic, Gemini, Groq, DeepSeek, Together, Mistral, xAI, ollama.com, local Ollama, vLLM — or pick custom in the wizard and point it at any OpenAI-compatible endpoint (LM Studio, a proxy, a private gateway). The setup wizard live-tests the connection before saving, so you know immediately if a key works.

Where does my data live?

In plain files you own: %LOCALAPPDATA%\aex on Windows, ~/.aex on Linux/macOS. Memory in MEMORY.md/USER.md, skills in skills/, session history in a local SQLite database, trajectories as JSON. Delete the folder and it's gone — no cloud account, no sync, no telemetry.

How is this different from a chat wrapper?

Chat wrappers are stateless. AEX Agent bounds its memory so context stays small, writes its own skills after real tasks, searches every past session with FTS5, schedules cron jobs that inject conversational memory, and exposes an OpenAI-compatible API so other tools can use it too. It compounds; wrappers forget.

Can I use it from other apps?

Yes — run aex gateway and point Open WebUI, LangChain, or any OpenAI-style client at http://localhost:8642/v1. Telegram, Discord, and Slack bridges are built in.

What does the telemetry bar show?

Model name, context window usage (~used/limit with a fill gauge), stream health, and per-round latency — updated live while the agent works, so you always know what's happening under the hood.
