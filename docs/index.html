01 — Capabilities

Built for long-horizon work,
not throwaway chats.

Every subsystem is designed to persist, recall, and compound — the opposite of a stateless chatbot wrapper.

/01

Persistent memory cabinet

MEMORY.md holds world facts, USER.md holds who you are — FIFO-bounded at 2.2K/1.4K chars so context never bloats. Every past session is FTS5-searchable from SQLite.

/02

Skills it writes itself

Finish a task once — the agent distills the procedure into an executable SKILL.md package and loads it into every future session automatically.

/03

Full-screen terminal TUI

Textual app: docked header, scrollable transcript, tool-call cards, and the live telemetry bar — context gauge, stream health, latency, token flow.

/04

Any provider, mid-session

Thirteen built-in providers plus custom for any OpenAI-compatible endpoint. Masked key entry with a live connection test before anything saves.

/05

Gateway + channels

FastAPI server on :8642 speaks OpenAI-compatible /v1/chat/completions — point Open WebUI or your stack at it, or bridge to Telegram, Discord, Slack.

/06

Cron & subagents

Natural-language scheduled jobs with memory injection, plus parallel subagent delegation that collapses long task chains into zero-context-cost turns.

02 — The closed loop

It gets better every time
you use it.

Four steps, one compounding cycle. The agent you close tonight is not the agent you open tomorrow.

STEP 1

Act

Terminal, files, web search, code sandbox — real execution with tool-call cards in view.

→
STEP 2

Distill

High-salience outcomes are folded into bounded persistent memory automatically.

→
STEP 3

Synthesize

Reusable procedures become executable skills via /learn.

→
STEP 4

Recall

Next session starts with skills, memory, and FTS5 history pre-loaded. Smarter on open.

03 — Install

Sixty seconds to
a sovereign agent.

No accounts, no telemetry, no lock-in. One pip install, point it at any model you already pay for.

$ pip install git+https://github.com/authxibu-cyber/AEX-Agentinstall straight from github
$ aex setupprovider · model · key — live-tested
$ aexfull-screen session
windows: .\scripts\install.ps1 · linux/macOS/wsl: ./scripts/install.sh

The setup wizard runs a live connection test against your real endpoint before saving anything. API keys are masked on entry and stored in AEX_HOME/.env — never in config.yaml.

Home lives at %LOCALAPPDATA%\aex (Windows) or ~/.aex — memory, skills, sessions, and trajectories in plain files you own.
